# Bearings live validation, round 3

The under-five-second target is not reliably met. With nine secondmates (six local and three using real OpenSSH), 813 cached contributions, 813 report pointers and 84 parent status lines per mate, the real `bin/fm-bearings-snapshot.sh --json` took 4.289s cold and 5.190s / 4.076s warm. The base took 19.909s. A separate sequence without competing tests took 6.168s, 5.666s, 5.512s, 4.175s and 4.501s. Four of eight healthy target runs exceeded five seconds. Both benchmark batches awaited all commands and retained every output and exit status; no result was dropped.

All eight fm-bearings.v1 outputs exactly matched the historical base with a fixed observation clock. Independent assertions checked nine fresh structured-home rows, 813 known readable contributions, the exact set of 813 report IDs, and nine surviving keyed decisions. Hashes confirmed 1,646 durable primary files were unchanged; only the documented observational caches were excluded.

The real snapshot CLI, fm-on.sh, OpenSSH server, fm-remote-entrypoint.sh, remote worker and fm-remote-file.sh were exercised. The client wrapper only selected a private SSH configuration and recorded call counts before execing /usr/bin/ssh; it generated no responses. Pausing the actual SSH server exercised the shared deadline and cache fallback. Missing and malformed remote ledgers stayed explicitly unknown, missing ledgers were not recomputed, and a sampling cap selecting two local homes caused zero SSH calls. Each uncapped run made exactly one SSH request per remote home. No collector remained after either batch.

Direct canonical CLI checks verified cold keyed decisions, appended captain-held resolution, cache invalidation on status rewrite, secondmate versus ship terminal behavior, UTF-8, tabs, trailing spaces and special-character report IDs. Bearings and contribution snapshot CLI checks verified live hold matching by task identity and explicit URL, while dated, blocked and unrelated rows stayed outside captain contributions. An initial driver assertion expected duplicate URL owners as separate contribution rows; it was corrected to the documented one-row-per-URL contract and the real --all output confirmed that both owner IDs were retained.

Targeted `tests/fm-classify-decision-key.test.sh` and `tests/fm-bearings-snapshot.test.sh` passed. The first Bearings invocation encountered fixture Git discovery contamination because TMPDIR was nested in the run worktree; re-running with GIT_CEILING_DIRECTORIES at .gate-test fixed the isolation and the entire focused file passed. These tests use simulated external boundaries and supplement, rather than establish, the live product results above. No complete repository suite, linter, formatter, static analysis, pipeline control, push, PR or CI phase ran.

All product data was disposable and created within this run worktree; no operator fleet data, credentials or configuration was used. Both disposable SSH containers were removed and their actual cleanup statuses checked. The test image and disposable worktree data are removed at closeout. This is a CLI change, so retained JSON outputs and timing transcripts show the end-user surface; no rendered UI changed and no screenshot was needed.
