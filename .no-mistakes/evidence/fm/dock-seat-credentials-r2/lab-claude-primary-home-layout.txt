  Purpose
  - config/claude-account (with config/pi-account): an optional pin that picks which account this home's Claude and Pi workers launch on. It stays on this machine only (not committed to git) and is
    not inherited by secondmate homes. If the file is absent, workers use whatever account is signed in by default. If it's present, a launch is refused unless the pinned account resolves and is
    signed in. Details are in docs/configuration.md under "Worker account pin", starting at line 824. The file holds one line: ordinary or an absolute path to a Claude config directory.
  - config/crew-dispatch.json: optional dispatch profiles, also kept only on this machine and inherited by secondmate homes. Firstmate maintains it, but a person can edit it. It holds plain-English
    rules that choose the runner, model, effort and optional seat for each crewmate or scout task. The schema is in docs/configuration.md under "Crew dispatch profiles", starting at line 970.
  Who may change a pin, and what to do when a launch is refused
  - The skill file (line 25) says: "only the captain chooses or changes a pin, so on a refusal report the needed login and never edit or remove the file to unblock a spawn."
  - docs/configuration.md adds (line 865): a malformed file, an unreadable directory or a signed-out account refuses the launch and names the file to fix. Firstmate never falls back to the default
    account, never changes a global login and never copies a credential.
  - For a raw Claude launch command that sets CLAUDE_CONFIG_DIR or a credential like ANTHROPIC_API_KEY, the refusal names that variable. The fix is to remove that assignment from the command, or to
    change or remove the pin (line 854). Under the skill's rule, changing the pin is your call, not firstmate's.
  - One gap: the "only the captain" rule appears only in the skill file. The "Worker account pin" section of docs/configuration.md doesn't say who may change the pin.
